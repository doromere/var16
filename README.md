# Фабрика светопрозрачных конструкций (вариант 16, ПР-23, шифр ОКН, ПМ.01)

Параметрический расчёт пластиковых/алюминиевых окон, расхода профиля, стеклопакетов и стоимости монтажа.
Avalonia UI + MVVM (CommunityToolkit.Mvvm) · EF Core (Pomelo MySQL/MariaDB) · xUnit.

## Структура решения (`WindowFactory.sln`)

| Проект | Назначение |
|---|---|
| `src/WindowFactory.Core` | POCO-модели, `AppDbContext`, сервисы бизнес-логики (расчёт, FSM, маска номера, SHA256, экспорт, раскрой, гарантия, валидация) — без зависимостей от UI |
| `src/WindowFactory.Desktop` | Avalonia: Views (XAML), ViewModels, Converters, Styles, Assets, DI-регистрация (`App.axaml.cs`) |
| `tests/WindowFactory.Tests` | xUnit, 37 тестов (4 обязательных по ПК 1.4 + дополнительные, в т.ч. интеграционные на SQLite с транзакциями) |

## База данных (MySQL / MariaDB)

1. Запустить MySQL/MariaDB (XAMPP или Linux), открыть <http://localhost/phpmyadmin/>.
2. Вкладка **«Импорт»** → выбрать `database/window_factory.sql` → выполнить (создаётся БД `window_factory`, 7 таблиц, демо-данные).
3. Строка подключения — `src/WindowFactory.Desktop/appsettings.json` (по умолчанию `root` без пароля) или переменная окружения `WINDOWFACTORY_DB`.

ER-диаграмма: `docs/erd.svg` / `docs/erd.png`.

## Запуск

```bash
dotnet run --project src/WindowFactory.Desktop
dotnet test
```

Требуется .NET 8 SDK.

## Демо-учётные записи

| Роль | Логин | Пароль |
|---|---|---|
| Главный технолог | `technolog`, `technolog2` | `Tech#2024` |
| Менеджер по замерам и продажам | `manager`, `manager2`, `manager3`, `manager4` | `Manager#2024` |

Пароли хранятся как SHA256 (hex). После 3 неверных попыток вход блокируется на 10 секунд с обратным отсчётом.

## Разграничение прав

- **Главный технолог** — редактирует справочники (профильные системы с ценой за метр, стеклопакеты), переводит заказ «Передано в цех» → «Изготовлено», выгружает карту раскроя; заказы — только просмотр.
- **Менеджер** — заказчики и заказы (Master-Detail), переводы «Замер выполнен» → «Передано в цех», «Изготовлено» → «Смонтировано», «Рекламация», экспорт карты раскроя и акта.

## Бизнес-логика (`OrderCalculationService`)

- S = w·h / 1 000 000, P = 2·(w+h) / 1000
- Позиция = P·price_per_meter + S·price_per_m2 + створки·2500 ₽ (фурнитура)
- `has_installation` → монтаж +20 % от стоимости конструкций
- подъём выше 5 этажа без лифта → +150 ₽ за каждый этаж свыше 5 (один раз на заказ, при монтаже)

## FSM (`OrderStateMachine`)

`Замер выполнен → Передано в цех → Изготовлено → Смонтировано / Рекламация` (из «Смонтировано» рекламация возможна в пределах 36 месяцев гарантии).

- Нарушения правил — `InvalidOperationException`.
- В цех нельзя передать пустой заказ (0 строк) и заказ с размерами вне ограничений профиля (ширина 400–1500 мм).
- Строки можно менять/удалять только в статусе «Замер выполнен».
- Рекламация требует причину (`cancel_reason`) не менее 10 знаков.

## Остальные требования

- Номер документа: `ПР23-ОКН-{Год}-{Номер:D5}` (`DocumentNumberGenerator`).
- Экспорт (`.txt` / `.html`): технологическая карта раскроя и акт приёма-сдачи; в нижней строке — SHA256 от `Номер|Дата|Контрагент|Сумма|КоличествоПозиций` (`IntegrityService`).
- `DispatcherTimer`: каждые 30 с пересчитывает гарантию (36 мес. со дня сдачи) и подсвечивает строки: красный — рекламация, оранжевый — гарантия истекла, жёлтый — истекает в течение 30 дней, зелёный — на гарантии. Также используется для блокировки входа.
- Сохранение заказа — транзакция (`BeginTransactionAsync`) и загрузка через `.Include(x => x.OrderItems)`; стоимость пересчитывается на стороне сервиса.
